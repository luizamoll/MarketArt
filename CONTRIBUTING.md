## Fluxo de trabalho

A branch `main` deve representar a versão estável do projeto.

Para cada alteração:

1. Crie uma branch a partir da `main`.
2. Use um nome curto e descritivo, por exemplo:
   - `feat/pagina-explorar`
   - `feat/perfil-artista`
   - `fix/menu-mobile`
   - `docs/atualiza-escopo`
3. Faça commits pequenos e com mensagens claras.
4. Abra um Pull Request para a `main`.
5. Revise a alteração no navegador antes de fazer o merge.

## Convenções do projeto

- HTML deve priorizar estrutura semântica e acessibilidade básica.
- CSS deve permanecer organizado e responsivo.
- JavaScript deve ser adicionado quando houver uma interação real a implementar.
- Funcionalidades planejadas não devem ser apresentadas no README como se já estivessem prontas.
- Mudanças de escopo definidas em aula devem ser registradas em `docs/ESCOPO.md`.

## Antes do merge

Confirme que:

- a página abre sem erros;
- links e navegação alterados funcionam;
- o layout continua utilizável em telas menores;
- não foram incluídos arquivos locais, temporários ou informações sensíveis;
- a documentação continua coerente com o que realmente está implementado.
