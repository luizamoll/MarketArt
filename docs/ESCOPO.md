# Escopo inicial do MarketArt

> Documento provisório. O conceito ainda está sendo amadurecido em aula e deve ser atualizado conforme a disciplina definir requisitos mais concretos.

## Problema que o projeto explora

Criadores de diferentes áreas artísticas precisam de espaços para apresentar trabalhos, enquanto compradores precisam conseguir descobrir artistas e produtos de forma organizada.

O MarketArt parte da ideia de reunir essas duas necessidades em uma experiência web única.

## Perfis considerados

### Artista / criador

Pode representar profissionais ou estudantes que produzem pinturas, ilustrações, artes digitais, fotografia, design ou outros trabalhos artísticos.

Possibilidades consideradas para o perfil:

- apresentação pessoal;
- portfólio;
- publicação de trabalhos;
- descrição, categoria e preço de itens.

### Cliente / comprador

Pessoa interessada em descobrir, visualizar e eventualmente adquirir trabalhos artísticos.

Possibilidades consideradas para o perfil:

- explorar trabalhos;
- visualizar detalhes;
- conhecer o perfil do artista;
- salvar ou comprar itens, caso essas funções sejam implementadas no escopo da disciplina.

## Telas consideradas para a primeira versão

- Página inicial
- Explorar artes
- Detalhes de uma obra ou produto
- Perfil do artista
- Cadastro / login
- Publicar arte

## Funcionalidades ainda não assumidas como implementadas

- autenticação real;
- persistência de usuários e produtos;
- carrinho;
- pagamentos;
- favoritos persistentes;
- sistema de mensagens;
- avaliações;
- painel administrativo.

Esses recursos só devem entrar na documentação como concluídos depois de realmente existirem no código.

## Decisões em aberto

- quais funcionalidades serão obrigatórias para a entrega;
- se haverá apenas protótipo de cadastro/login ou comportamento funcional;
- se o projeto utilizará armazenamento local ou algum back-end;
- como a comercialização será representada;
- identidade visual final;
- quantidade de páginas e nível de interatividade exigidos pelo professor.
